# 낙상 상태 표시와 브라우저 음성 — 2026-10-29

## 무엇을 복원했나

산업안전 앱으로 분리할 때 단순화된 화면에서 영상 위의 큰 경보 배지와
확인 전까지 유지하는 알림이 빠졌다. 현재 상태만 1초마다 표시하므로 빠르게
바뀌는 판정을 놓치거나 감지 후 추적이 사라지면 경보가 사라진 것으로 보일 수 있었다.
모델·임계값 문제로 단정하거나 감도/FPS를 변경하지 않고 **표시·알림 계층만** 보완했다.

| 현재 상태 | 영상 위 표시 | 의미 |
| --- | --- | --- |
| normal | 관측 중 | 확정 경보 없음. 안전 보증이 아님 |
| suspected | 노란색 `낙상 의심` | 움직임을 확인 중, 확정 전 |
| fallen | 붉은색 `낙상 감지` | AI 확정 경보. 현장 확인 필요 |
| recovering | 파란색 `낙상 회복 중` | 회복 동작 관측, 부상 없음/사고 해결 보증이 아님 |
| unobserved | 판정 대상 없음 | 유효한 추적 대상 없음, 회복으로 간주하지 않음 |
| 연결 오류 | 분석 연결 끊김 | 최신 상태를 알 수 없음. 과거 판정을 현재처럼 표시하지 않음 |

배지는 HTML/CSS이며 WebRTC 원본과 MJPEG 분석 영상 양쪽에 표시된다.
박스·관절 좌표용 canvas를 추가하거나 영상을 재인코딩하지 않는다.
현재 AI 상태를 안내하므로 브라우저 영상 지연과 완전히 동기화된 표시는 아니다.
박스·관절은 기존의 **분석 영상 · 박스·관절** 모드에서 확인한다.

모델의 `움직임 분석 중` 준비 상태와 낙상 판정은 다른 값이다.
1초 조회 사이에 끝난 전이도 감지 기록에서 확인하며, 마지막 전이를 분석 정보 아래에 표시한다.
확정된 낙상은 별도의 **확인이 필요한 낙상 감지 기록**에 시각과 함께 남긴다.
이는 현재 판정을 덮어쓰지 않는다. `기록 확인`은 이 탭의 안내만 접는다.
모델 초기화·사고 해결·저널 삭제·다른 브라우저의 확인 처리를 하지 않는다.

미확인 기록은 최신 1개(id/시각만), 확인한 id는 최대 50개를 sessionStorage에 유지한다.
새로고침 또는 서버 재시작 뒤에도 같은 탭의 미확인 안내는 남는다. 탭을 닫으면
탭 저장소의 수명에 따르며 영구 사고 기록이 아니다. 캡처 보존 기간은 그대로 1시간이다.
저장소가 차단되면 현재 페이지 메모리에서만 유지한다.

## 음성 사용

1. **목소리 선택**: 영상 모드와 같은 드롭다운에서 두 버전을 선택한다.
   - `자연스러운 음성 · 안내형` (기본): 사전 생성한 SunHiNeural 한국어 음성 파일.
   - `기존 음성 · 브라우저 TTS`: 처음 도입했던 Web Speech API 경로를 그대로 유지.
   목소리 선택만 localStorage에 저장한다. 선택을 바꿔도 소리를 내거나 자동 알림을 켜지 않는다.
2. **소리만 테스트**: 선택한 목소리로 “낙상이 감지되었습니다.”를 한 번 재생.
   자동 알림 설정을 바꾸지 않는다. 안내형은 고정 MP3 GET만 사용하며 제어 API 쓰기,
   실제 낙상, 캡처, Pi4/MQTT 동작을 만들지 않는다.
3. **음성 알림 켜기**: 안내형에서는 확인음, 기존 음성에서는 활성화 문장을 재생한다.
   활성화 자체를 낙상으로 오해하지 않도록 안내형의 낙상 문장을 여기서는 읽지 않는다.
   이후 새 `fall_confirmed`에 안내형은 “낙상이 감지되었습니다.”,
   기존 음성은 “낙상이 감지되었습니다. 현장을 확인해 주세요.”를 안내한다.
4. **음량**: 0–100%, 기본 80%. 다음 재생부터 적용. OS/브라우저 음량과 별개다.
   0% 또는 음성 알림 끄기는 진행 중인 소리도 중지한다.

사용자 클릭 후 활성화한다. 자동 활성화를 저장하지 않으므로 새로고침하면 다시 켜야 한다.
새 이벤트 ID로 중복 방지(최대 200개); 동일 이벤트를 계속 조회해도 다시 읽지 않는다.
동일 조회에서 여러 확정 이벤트가 오면 한 번 안내한다. 음성 큐를 쌓지 않고 최신 안내로 교체한다.
의심/회복/해제 단계는 시각적으로만 표시한다.

첫 조회의 과거 이력은 읽지 않는다. 탭이 숨겨졌다가 돌아온 첫 조회 또는
마지막 성공 조회와 15초 이상 차이 나는 재접속은 다시 기준 이력으로 삼아 소리를 내지 않는다.
이때 놓친 확정 경보는 기록 안내에서 확인한다. 따라서 백그라운드/잠금/절전 상태의
항시 안전 경보기로 사용할 수 없으며 탭을 켜 둔 운영 확인용이다.

## 음성 엔진과 실패 대응

### 자연스러운 안내형

이전 프로젝트에서 생성했던 고정 문구 `ko-KR-SunHiNeural`, rate -5% 음성을 재사용한다.
원본은 수정하지 않았고, 출처/원본 체크섬은 `static/audio/README.md`에 기록했다.
새 앱에는 독립적인 `static/audio/fall-detected-ko-sunhi-v1.mp3`만 포함한다.
23,660 bytes, mono 24 kHz MP3, 약 2.9초. 개인정보·카메라 소리가 없는 합성 문장이다.
운영 시 합성 API/키·TTS 패키지·이전 저장소·Pi4가 필요 없다.

동일 출처에서 가져온 파일을 Web Audio로 디코드해 탭 안에서 버퍼 1개를 재사용한다.
파일은 256 KB 이하/디코드 길이 10초 이하로 제한한다. 읽기 시간 제한 4초,
준비 시간 제한 6초. 준비 실패 시 **기존 음성으로 대체**한다고 표시하고 기존 TTS를 시도한다.
재생 요청을 큐에 쌓지 않고 목소리 변경/새 재생/끄기/음량 0/탭 숨김에 이전 소리를 중단한다.
6초가 지나거나 취소된 준비 요청이 뒤늦게 완료되어도 그 음성을 뒤늦게 재생하지 않는다.

### 기존 브라우저 TTS (유지)

Web Speech API의 한국어 음성을 사용하며 로컬 한국어 음성을 우선한다.
목소리 종류·발음·제공 여부는 접속 기기의 OS/브라우저에 따른다.
한국어 음성이 없거나 재생 오류/4초 내 시작 응답이 없으면 Web Audio 경고음으로 대체한다.
완료 응답이 없는 음성은 15초에 중지해 무한 대기를 막는다.
현재 탭에는 AudioContext 하나와 안내형 버퍼 하나를 유지하며 동시에 소리를 겹쳐 재생하지 않는다.
음성/경고음 모두 사용할 수 없으면 재생 허용·음소거 확인 안내를 표시한다.
API 완료 응답이 실제 스피커에서 사람이 들었다는 증거는 아니다.

음성 입력·마이크 권한은 필요 없다. Pi5에는 고정 MP3만 추가하며 TTS 합성 엔진/외부 API는 설치하지 않는다.
비로컬 OS 음성을 선택하는 환경은 브라우저 엔진의 네트워크 정책을 따르며,
앱이 음성 엔진에 보내는 문구에는 이름·영상·카메라 계정이 없다.
같은 정적 스크립트로 LAN HTTP 및 기존 HTTPS에서 동작한다. WebRTC 연결 성패와 독립적이다.

기술 근거:
[기기에서 제공하는 음성 목록](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices),
[사용자 클릭 기반 AudioContext 활성화와 음량 제어](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices),
[음성 오류 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/error_event).
안내형 구현 근거:
[오디오 파일 디코딩](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData),
[버퍼를 재사용하는 오디오 재생](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode).

## 검증과 범위

`tests/browser_alert_check.py`는 실제 템플릿/JS/CSS를 Chromium에서 실행한다.
카메라·모델을 기동하지 않고 모든 API 응답과 음성 엔진을 브라우저 테스트 안에서 대체한다.
별도 브라우저 컨텍스트에서는 실제 MP3 디코드/재생 완료도 확인하되,
Chromium `--mute-audio`로 물리 스피커 출력은 차단한다.
낙상 상태 전이, 미확인 안내/확인, 과거 이력 무음, 반복 음성 방지, 의심·회복 무음,
조회 사이에 끝난 확정, 연결 끊김, 숨김 탭 복귀, 음량, 음성 없음/실패/무응답 대체,
390/768/1440 화면 폭과 다크/라이트 모드를 검사한다. 테스트는 실제 소리를 내지 않는다.
서버의 감지 이벤트를 만들거나 실제 낙상을 요청하지 않는다.
두 음성 선택/저장, 안내형 테스트 및 자동 경보, 버퍼 재사용, 파일 실패 대체,
선택 변경 중 늦은 음성 재생 취소도 검사한다.

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
# Playwright 설치된 별도 테스트 Python + /usr/bin/chromium 필요:
/tmp/industrial-fall-browser.eSvnyj/bin/python tests/browser_alert_check.py
```

실제 목소리·음량은 사용자의 PC/휴대폰에서 `소리만 테스트`로 최종 확인해야 한다.
Hailo 모델·EdgeFall 계약·RTSP·인코딩·MediaMTX·드라이버·차량 코드는 이번 변경 대상이 아니다.

### 이번 배포 실측

- 기존 Python 단위 테스트 43개 통과.
- 오프라인 Chromium 상태/음성 모의 테스트 통과(실제 발화 없음).
- 실제 서비스 브라우저 시험: WebRTC 수신 프레임 증가(`frames_decoded=22`,
  loopback/host UDP), 분석 MJPEG, WHEP 실패 시 원본 MJPEG 전환, 캡처 대화상자 통과.
- 배포 후 카메라·분석 정상, 분석 약 13.9 FPS, Hailo 약 14.9 ms인 표본 확인.
  HTTPS 대시보드 HTTP 200. 외부 NAT에서 WebRTC 성공했다는 뜻은 아니다.
- 실제 낙상·실제 스피커 재생을 발생시키는 테스트는 하지 않았다.

- `https://vision.aihous.site` 배포 화면에서도 안내형 재생 완료, WebRTC/분석 MJPEG,

  외부 NAT의 WebRTC 성공 근거로 사용하지 않는다.
