# 검증 기록과 다음 단계

## 코드 검증 (2026-10-29)

34개 자동 테스트 통과:

- 기존 Hailo 좌표 변환/EdgeFall native 단위 계약·기하+시간 gate 테스트.
- 느리게 눕기·빠른 숙이기 등 synthetic pose fixture 회귀 테스트.
- 로컬 상태 전이/중복 방지 256개/이벤트와 이미지 각 50개/캡처 TTL·크기 제한.
- 동일 프레임 박스·관절, 연속 동일 프레임 재추론 금지, 재연결 시 관측 초기화.
- MQTT/얼굴/Pi4 제어 route 부재, WHEP same-origin/고정 대상, 구독 제한/해제.
- 최근 입력과 추론 상태를 반영하는 health(200/503), 순환 로그.

`scripts/check_runtime.py` 사전 검사 통과. HEF checksum 및 native ABI/profile 일치.
이는 실제 산업 현장의 정확도 시험이 아니다. 합성 fixture 통과를 recall 수치로 사용하지 않는다.

## 실장비·웹 전환 확인 (2026-10-29)

- 새 서비스 2개 active/enabled, 이전 Pi5 서비스 2개 inactive/disabled.
- LAN 및 기존 HTTPS `/health` 모두 camera_online/analysis_online=true, HTTP 200.
- 실제 Dahua 입력 약 15 FPS, 분석 약 13.6–13.8 FPS, Hailo 추론 약 15–16 ms.
  이는 짧은 관측치이며 끝단 영상 지연 또는 장시간 보장치가 아니다.
- 서버 프로세스 RSS 스냅샷: 이전 약 482 MiB → 새 약 315 MiB.
  카메라 수/동시 작업이 달라 엄밀한 동조건 벤치마크는 아니다.
- Pi5에서 1883/1884/8000/8081로 연결된 TCP 세션 없음. MQTT import/발행 코드 없음.
- Chromium에서 LAN과 `https://vision.aihous.site`의 WebRTC 원본 재생,
  MJPEG 박스·관절, 강제 WHEP 실패 시 원본 MJPEG 전환, 모바일 가로 넘침 없음,
  테마 유지 및 JavaScript 오류 없음 확인.
- 브라우저는 Pi5 LAN에서 실행했다. 공개 도메인을 통한 신호 교환은 확인했지만,
  서로 다른 외부 NAT의 WebRTC 직접 연결 성공까지 보장하지 않는다.
- 낙상 빨간 배너/캡처 다이얼로그는 브라우저 로컬 fixture로 검증한다.
  실제 서비스에 가짜 경보나 외부 알림을 발행하지 않는다.

## 산업 현장에서 추가할 검증

1. 실제 설치 각도·거리·조명에서 머리부터 발끝까지 보이는 구도 확인.
2. 보호복·안전모·다인원·물체 가림에서 관절 누락 측정.
3. 작업 중 앉기/숙이기/무릎 꿇기/물건 줍기 등 정상 동작에 대한 시간당 오탐.
4. 안전 매트·보조인력이 있는 통제된 연기 또는 동의받은 영상으로 방향별 감지율.
5. 동작 시작→알림, 카메라 촬영→브라우저 표시의 끝단 지연을 따로 측정.
6. 네트워크 단절/복구, 카메라 재부팅, 24시간 자원 사용 및 기록 상한 확인.

실제 위험 차량 동작/제어, 경보 전달 신뢰성/인증. 차량 연동은 이번 범위 밖이다.
